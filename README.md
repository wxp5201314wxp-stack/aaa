# 仓序 · 进销存系统

中文版单仓库进销存应用，使用 Python 标准库和 SQLite，无第三方依赖。

## 启动

```sh
cd /workspace/aaa
python3 app.py
```

在运行机器的浏览器访问 `http://127.0.0.1:8000`。默认仅监听本机。可通过 `PORT` 改端口，`HOST` 改监听地址；此版本没有身份认证，请仅在可信本机环境使用，不要直接暴露到公网。

## 功能

- 商品档案：唯一编码、分类、单位、采购价、售价、预警库存
- 采购入库与销售出库：往来单位、数量、实际单价、备注
- 事务更新库存与流水，禁止库存不足时出库
- 今日采购销售金额、按商品采购价计算的库存总值、七天数量趋势
- 库存搜索、预警筛选、CSV 导出

初始数据为空，无演示数据。先新增商品，再通过采购入库建立库存。
金额以整数分保存；数量为整数。库存总值是参考采购价乘当前库存，不是会计存货成本核算。
单据日期使用北京时间。此版本不包含登录权限、多仓库、退货、应收应付和财务核算。

## 数据与备份

数据库默认保存至 `data/inventory.db`，重启后保留，可用 `INVENTORY_DB` 指向其他位置。
备份时先停止服务，再复制数据库文件。不要将真实业务数据库提交到 Git。

## 验证

```sh
python3 -m unittest discover -s tests -v
```

测试使用独立临时数据库，验证商品创建、金额保存、出入库、库存不足拦截、错误输入和重启持久化。

## 手机扫描商品条码

- 新增商品中点「扫码填写商品编码」，识别后自动填写商品编码，不自动保存。
- 入库 / 出库单中点「扫码选择商品」，按编码匹配已建档商品，不自动提交单据。
- 页面顶部「扫码查商品」可识别条码并筛选库存。
- 支持 EAN-13、EAN-8、UPC-A/E、Code 128、Code 39、ITF。普通文字编码不属于条码识别；商品名、价格仍需自行填写。
- 手机访问 `http://局域网IP:8000` 时，使用「拍照 / 选择图片」识别；浏览器通常禁止该地址直接启动实时摄像头。实时扫码需要 HTTPS 或本机 localhost，以及摄像头权限。拍照入口是否直接打开相机取决于手机浏览器，也可选择相册照片。
- 图片在浏览器本地处理，不上传。识别后请核对编码，尽量只保留一个完整条码，避免模糊反光。
- 本地附带 html5-qrcode 2.3.8（Apache-2.0，许可证见 `static/vendor/html5-qrcode.LICENSE`），无需 CDN。真实手机摄像头兼容性需在实际设备验证。

## 待补价销售、编辑单据与日期汇总

销售出库的本次单价默认留空，可先保存并扣库存，单据显示「待补价」。显式填写 0 表示零元销售，和待补价不同。入库单价仍为必填。

在销售出库、出入库记录或首页最近流水中点击「编辑 / 补价」，可修改销售数量、单价、客户、备注及业务时间；不能更换商品。补价不重复扣库存，改数量只调整库存差额，库存不足会拒绝保存。

出入库单均可填写业务时间，按北京时间保存。采购、销售和出入库记录页面支持开始 / 结束日期（含两端）、「今天」和「全部日期」，显示所选范围和业务类型的入库金额、已定价出库金额、待补价笔数。查看同一天全部出入库金额，请进入「出入库记录」，将两个日期设为同一天。待补价单不计入金额；之后补价会回计到业务时间所属日期，并非补价当天。汇总为业务单据金额，不代表收付款金额。

### 升级已有 Mac 安装

1. 终端按 Control+C 停止旧服务。
2. 备份整个 `data` 文件夹。
3. 用新版 `app.py` 和整个 `static` 文件夹替换旧版，保留原 `data`。
4. 重新执行 `HOST=0.0.0.0 python3 app.py`，首次启动自动升级数据库，保留原商品和流水。
5. Mac 使用 Command+Shift+R 刷新；手机刷新页面，必要时关闭标签页后重新打开。

旧版记录保持原金额和业务时间，已有零元记录不会自动变成待补价。升级数据库后不要换回旧版 app.py；如需回退，应同时恢复升级前数据库备份。

## 在库库存编辑与我方运费

在「商品与库存」找到商品，点击「编辑库存」，填写调整后的实际数量和调整原因。数量必须为非负整数，库存调整记录会保留原数量、新数量、差额、原因和北京时间。调整不产生采购 / 销售金额，也不修改原单据，适合盘点修正、损耗或初始库存补录。正常采购销售仍应使用出入库单。若打开弹窗后库存发生变化，会拒绝覆盖，请刷新后重新调整。

销售出库单新增「我方承担运费（元）」，按该单整笔运费填写（不是每件运费），默认 0，可在「编辑 / 补价」中修改。运费为我方支出，不加进客户销售金额，也不改变商品采购价或库存。待补价销售也可先记录运费。流水单独列出运费，今日销售卡片及日期筛选汇总分别显示运费，按单据业务日期统计；这不是实际支付日期或利润核算。

升级时先停止服务并备份 `data`，替换新版 `app.py` 和整个 `static` 后重新启动，保留原 `data`。历史单据运费默认 0；原有库存和流水保留。

## 提前制采购单与确认入库

新增采购入库单时，「确认入库（货已收到）」默认勾选，保持原先直接入库的操作。货未到时取消勾选，保存为「待入库」：保留采购数量、金额、供应商和制单业务时间，但不增加库存、不增加可售数量、不计入入库金额或流转趋势。

到货后，在采购入库、出入库记录或首页最近记录中点击该单「确认入库」，核对商品与数量，填写实际入库时间（默认北京时间当前时刻）并保存。整单确认后增加库存，金额和流转数量按实际入库日期统计；原制单时间仍保留展示。重复请求或同时确认只入库一次。当前不支持分批到货、撤回确认或修改采购单。

日期筛选：已确认采购按实际入库时间筛选；待入库采购按原制单业务时间筛选。所选范围单独显示待入库笔数，金额合计排除待入库单。历史采购记录在升级后保留为「已入库」，沿用原业务时间作为入库时间，不重复增加库存。

升级仍需先停止旧 Python 服务，备份 `data`，同时替换新版 `app.py` 和整个 `static` 文件夹，保留原 `data` 后重新启动、刷新浏览器。仅替换前端会导致旧后端提示「接口不存在」。
